# memory/gotchas.md — Грабли, лимиты и подводные камни

## 1. Telegram API & Экранирование
- **MarkdownV2 парсинг:** Telegram выбрасывает ошибку `Bad Request: can't parse entities`, если в тексте ответа есть неэкранированные спецсимволы MarkdownV2 (`.`, `!`, `-`, `(`, `)`, `_`, `*` и др.). В `src/` используется специальный хелпер очистки/экранирования. Всегда используй хелперы отправки сообщений вместо сырого `ctx.replyWithMarkdownV2` с непроверенным LLM-текстом.
- **Telegram Rate Limits:** При рассылках (`broadcast`) и постинге в каналы лимит составляет не более 30 сообщений в секунду для разных чатов и не более 1 сообщения в секунду в один и тот же чат/канал. Для этого используется очередь `BullMQ` с `limiter`.

---

## 2. ESM и Импорты в Node.js
- Проект использует чистый ESM (`"type": "module"` в `package.json`).
- **Все локальные относительные импорты ОБЯЗАНЫ содержать расширение `.js`** (например, `import { pool } from './database.js';`). Без `.js` Node.js упадет с ошибкой `ERR_MODULE_NOT_FOUND`.
- `__dirname` и `__filename` не определены по умолчанию в ESM. Используй `fileURLToPath(import.meta.url)` и `path.dirname()`.

---

## 3. Микросервис Semantica & Фолбэки
- Микросервис `semantica-service` работает по HTTP на порту 8081.
- Имеет жесткие таймауты: `SEMANTICA_TIMEOUT_MS` (по умолчанию 180ms) для выборки контекста, чтобы не задерживать ответ пользователю.
- Если сервис недоступен или ответил ошибкой, пайплайн обязан выполнить **graceful fallback** (использовать недавнюю историю из PostgreSQL без семантических векторов), а не прерывать генерацию ответа.

---

## 4. База данных и соединения
- При выполнении транзакций через `const client = await pool.connect()` обязательно помещай работу в блок `try ... finally { client.release(); }`. Забытый `release()` быстро исчерпает пул соединений PostgreSQL (`max: 20`) и повесит все запросы.
- Числовые типы PostgreSQL (`BIGINT`) приходят в JS как `string` или `BigInt`. Обращай внимание при сравнении `telegram_id`.

---

## 5. Radiant Engine Concurrency
- Суточный цикл Radiant (`day_runner.js`) обновляет состояние потребностей и текущего действия персонажа в фоне.
- При формировании контекста ответа (`context_builder.js`) данные Radiant считываются атомарно из кэша/репозитория, чтобы состояние не мутировало посреди сборки промпта.

---

## 6. Запуск тестов
- Тесты написаны под встроенный `node:test` раннер: `npm test` (`node --test --test-force-exit test/*.test.js`).
- Флаг `--test-force-exit` необходим, так как открытые пулы Redis и Postgres могут удерживать event loop активным после завершения ассертов.

---

## 7. Генерация картинок и дедупликация в канале
- **Запрет текста на AI-картинках:** Диффузионные модели (Gemini, Imagen, Flux) рендерят текст, если в промпте передавать текст поста. В `src/services/image_generator.js` и `src/channel_poster.js` используется строгое правило `STRICTLY NO text, words, letters, captions` и передается только описание сцены/вайба.
- **Строгий запрет повторов в канале:** В `getRandomLeraPhoto({ excludeChannelUsed: true })` и `getRandomChannelContent({ excludeRecent: true })` отключен LRU-повтор: если все фото/мемы уже были в канале, возвращается `null`, чтобы не спамить дубликатами. При генерации AI-фото его ID (`photo:${id}`) сразу связывается с `provenance.media_content_id`.

## 8. Мультимодальный пайплайн и голосовые сообщения
- **Изоляция Follow-up для `send_voice`:** При вызове тула `send_voice` нельзя скармливать синтезированный текст обратно в LLM с инструкцией «ответь своими словами». Модель может счесть это дублированием и выдать мета-рассуждения («НЕ повторяй текст...»).
- **Дебаунс и `typing_manager`:** В `flushUserBuffer` для вызова `startTyping` обязательно используется `buf.batchId || String(userId)`, чтобы `stopTyping` в очереди `queue.js` корректно очищал интервал отправки `sendChatAction`.
- **Строгий запрет повтора фото в личном чате:** В `findLocalPhoto` (`send_photo.js`) удален сброс фильтра `sentPhotoIds`. Если все локальные фото из базы просмотрены, бот не крутит их повторно, а генерирует новое фото через нейросеть либо честно отказывает.

## 9. Telegram Guest Mode (Bot API 8.0+) & Платежные методы
- **Guest Mode (`guest_query`):** При вызовах `@gexyy_bot <запрос>` в чатах, где бот не состоит в участниках, Telegram присылает обновление `guest_query`. Отвечать в такие чаты можно ТОЛЬКО через `bot.telegram.callApi('answerGuestQuery', { guest_query_id, result: { type: 'article', id, title, input_message_content: { message_text } } })`. Обычный `sendMessage` в чужой чат выбросит 403 Forbidden.
- **Коллизия REACTION режима в Guest Mode:** Telegram Bot API не поддерживает эмодзи-реакции на гостевые запросы. Для любого публичного/гостевого контекста (`isPublicContext: true`) флаг `allowReaction` принудительно отключается (`allowReaction = false`), чтобы классификатор интентов не сбрасывал текстовый ответ в пустую строку (`text: ''`), а всегда вызывал LLM для генерации ответа.
- **Нормализация параметров зачисления балансов (`processPlategaPayment`, `grantPackage`):** Всегда поддерживать гибкие сигнатуры аргументов (как строковый `packageType`, так и раздельные числовые `textCount`/`imgCount`), чтобы не терять начисления при вызовах из разных частей бота, админки и вебхуков.

## 10. Мультидиалог в группах и генерация медиа
- **Свежая генерация фото (`send_photo`):** В группах и гостевом режиме принудительно отключается `allow_db_fallback` (`allowFallback = false`). Фото всегда генерируются на лету через нейросеть, предотвращая ситуации, когда один участник видит повторы готовых картинок из галереи базы данных, которые уже видел другой.
- **Одиночный перенос строк вместо `|||`:** В гостевом режиме и группах разделитель лесенки `|||` заменяется на одиночный перенос строки `\n` без двойных пустых строк, сохраняя компактность и естественность реплик.

---

## 11. Reasoning-модели (DeepSeek/Qwen) и Tool Calling
- **Обязательный массив `required` в JSON Schema тулов:** Reasoning-модели перед вызовом инструментов строят логическую цепочку внутри `<think>`. Если поля схемы опциональны, модель может решить не вызывать инструмент, а спросить пользователя об одежде в мыслях и закрыть `</think>` с пустым `content`. Обязательно указывать `required: ["prompt", "outfit", "time_of_day"]` в `send_photo.js` и запрещать переспрашивать лук в описании параметров.
- **Graceful Silence вместо шаблонных заглушек:** В публичном контексте (`isPublicContext: true`) при сбое валидатора или пустом ответе после ретрая движок возвращает пустой текст `""`. В `channel_comments.js` при пустом тексте сообщение в чат не отправляется (бот просто молчит), сохраняя реализм живого человека и исключая шаблонные фразы («ой я тут зависла»).
