# План улучшения Admin v2: AI Sandbox & Prompts, цвета и компоненты

## Цель

Сделать админку более цельной и безопасной для ежедневной работы, а AI Sandbox — понятным рабочим местом для тестирования и публикации prompt-конфигураций, а не набором технических полей.

Область обзора:

- весь `admin-v2`: палитра, базовые компоненты, типографика, feedback и адаптивность;
- углублённо: `AI Sandbox / Prompt Studio` в `admin-v2/src/main.jsx`;
- проверен живой неавторизованный экран входа; Sandbox анализировался по исходному коду и контрактным тестам, потому что для настоящей сессии нужны ключ админки и API-данные.

Ограничение реализации: не вводить второй styling system и не мигрировать админку на Tailwind/shadcn. Оставить plain CSS и текущую папку `components/ui`, постепенно добавив семантические токены и недостающие примитивы.

## Принцип целевого интерфейса

**AI Sandbox — это workbench для решения «какой ответ и конфиг выпускать», а не raw-config form.**

Оператор должен в любой момент понимать:

1. какой intent, provider/model и вариант он тестирует;
2. что изменено только локально, что сохранено в Draft и что находится в Production;
3. почему A и B отличаются;
4. что именно попадёт в Production после подтверждения.

## Целевой AI Sandbox

### Шапка workbench

```text
AI Sandbox / Prompt Studio
CASUAL · Черновик v12 · Production v10 · есть несохранённые изменения
Provider: OpenAI · model: gpt-…          [Сохранить черновик] [Проверить изменения] [Опубликовать]
```

- Статус изменений остаётся всегда видимым.
- «Проверить изменения» открывает diff Draft против Production, а не только A против B.
- Публикация остаётся отдельным подтверждённым действием; текущий `ConfirmAction` переиспользуется.

### Левая панель: конфигурация

1. intent и A/B-переключатель;
2. версия Draft / Production;
3. сценарные sampling-пресеты и базовые параметры;
4. «Модули промпта», «Переопределения контекста», «Контекст пользователя» и продвинутые параметры — в disclosure-блоках;
5. любые активные overrides отражаются badge-ами в шапке чата.

### Центральная панель: диалог и результаты

- Перед composer: активный intent, подключённый пользовательский контекст и число сообщений истории.
- В A/B: два ясных результата или переключатель вариантов с фиксированной сводкой различий.
- У результата: ответ, provider/model, latency, tokens, «Почему такой ответ», редактирование и «Продолжить с вариантом».
- Отредактированный вручную ответ маркируется как «изменён в Sandbox» и не смешивается с provider output.
- Debug/raw prompt остаётся раскрываемой экспертной секцией с существующим обещанием не показывать секреты и скрытые рассуждения.

## Палитра и токены

Сначала добавить алиасы в текущий `:root`, затем заменить прямые значения только в затронутых компонентах. Не нужна одномоментная миграция в новую цветовую модель.

| Назначение | Токен | Значение |
|---|---|---|
| Canvas | `--color-canvas` | `#09090B` |
| Surface base | `--color-surface-1` | `#141416` |
| Surface inset | `--color-surface-2` | `#18181B` |
| Raised / interactive | `--color-surface-3` | `#202024` |
| Border default / strong | `--color-border` / `--color-border-strong` | `#2D2D33` / `#45454D` |
| Text primary / secondary / tertiary | `--color-text-*` | `#F4F4F5` / `#C4C4CC` / `#9B9BA5` |
| Accent / hover / subtle | `--color-accent-*` | `#60A5FA` / `#93C5FD` / `#172554` |
| Success | `--color-success` / `--color-success-bg` | `#4ADE80` / `#102A1A` |
| Warning | `--color-warning` / `--color-warning-bg` | `#F4B942` / `#3D2D0B` |
| Danger | `--color-danger` / `--color-danger-bg` | `#F87171` / `#351316` |

Перед выпуском обязательно измерить контраст именно на финальных rendered-парах; таблица — направление системы, а не декларация уже проверенной AA-совместимости.

## Компонентная база

| Компонент | Минимальный контракт |
|---|---|
| `Button` | primary, secondary, ghost, danger; 40px default, 32px compact; loading, disabled, focus-visible |
| `IconButton` | доступное имя, понятный tooltip, 40×40px default |
| `Card` | default, compact, interactive, inset; единые radius/padding/border |
| `Badge` / `StatusChip` | семантический статус с текстом и, где нужно, иконкой; не только цвет |
| `FormField` | label, hint, error, required/optional, связанный aria-description |
| `InlineNotice` | info, success, warning, error; без подмены toast-ом |
| `Toast` | typed feedback, корректные ARIA-роли, не исчезает преждевременно при ошибке |
| `EmptyState` | причина отсутствия данных + ясное следующее действие |
| `Dialog` / `ConfirmAction` | единый destructive/publish flow; всегда объясняет последствия |

Правила геометрии: radius 8px для controls и nested surfaces, 12px для главных карточек/dialog; spacing scale 4/8/12/16/24/32; transition только на конкретные свойства и с поддержкой `prefers-reduced-motion`.

## Рассмотрено, но не берём сейчас

| Идея | Почему не сейчас |
|---|---|
| Светлая тема | Нет продуктового запроса и контраста для неё; это отдельная тема, а не побочный эффект рефакторинга токенов. |
| Заменить все `<details>` модалками | Технические детали Sandbox логично скрываются progressively; достаточно улучшить статусы и подписи. |
| Мигрировать админку на Tailwind/shadcn | Уже есть React-примитивы и plain CSS; миграция увеличит риск и не решает workflow-проблемы. |
